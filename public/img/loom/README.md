# Loom posters

Generated by `npm run gen:loom-posters`, which boots the real rig in a
headless browser and renders one frame. Nothing approximates the engine,
so a poster cannot drift from what the live stage draws.

It is **not** a build step: it needs a browser and takes seconds per
product. Run it when a rig, a default pose or the charting face changes,
and commit the output.

## What is here

| File | Product | Stands in for |
| --- | --- | --- |
| `alphabet-blanket.webp` | The Armenian Alphabet Blanket | the stage before it loads, and permanently on a `low` device |
| `name-bib.webp` | The Custom Name Bib | the same, and it is the only render of a product that has no cover photograph at all |

## The generator is hermetic

It serves this repo's own `src/styles/fonts.css` and `public/fonts/` from
a loopback server and touches the network not at all. That is deliberate:
it used to load the faces from `fonts.googleapis.com`, which meant it
failed differently on every machine and, behind a proxy, reported a
missing typeface when the real problem was a missing route.

## Why the generator refuses to bake a fallback face

A canvas does not throw when a webfont is missing; it silently draws in a
fallback. `document.fonts.check()` does not help — it can return `true`
because a fallback family satisfies the query. So the generator measures
instead: two stacks naming the same fallback produce identical advance
widths only when the real face is absent.

This matters most for the name bib, which is machine embroidery in a
script face. Baked in a fallback serif it reads as *print*, not stitching
— a quietly wrong product photo shown to every visitor whose device
cannot run the 3D.

The blanket is guarded the same way, in both scripts, because the
charting family is split into subset files and either can be missing on
its own. The guard used to require `Fraunces` measured on Armenian text,
which is a check that can never pass: Fraunces has no Armenian coverage,
so the measurement always matched the fallback and the run always failed.
Charts come from Noto Serif Armenian now — see `STITCH_FONT_STACK` in
`src/loom/stitch/rasterize.js`.

## What does NOT get a generated poster

The Hye Em Yes bib. It is photo-led — there are five photographs of the
real piece, including the one this rig was modelled from — and its stage
uses the product's own cover photograph as its poster. A photograph of the
actual hand-stitched bib is both a better fallback and a better LCP image
than a render of it. Generated posters are for pieces whose fallback is
not a photograph.
